# 激光检测：极简 ROI 方案（2026-10-22 重写）

`k230/board/laser_openmv.py` 已被**整体重写**为极简版：
**给定 ROI，用 cv_lite 灰度阈值找最大 blob**。VERSION = `2026-10-22.8-roi`。

上一版（`.6-adaptive`/`.7-diag`）里的这些东西**全部删除**：
先验复核、评分公式、候选过滤、`pending` 多帧确认、大块取亮核、自适应阈值、
`_blob_pixels` 逐像素扫描。

---

## 1. 为什么之前是 110~209ms

旧实现两个致命开销：

1. `img.find_blobs()` —— OpenMV 原生全图搜索（实测 **11~24ms**，640×480）；
2. 对**每个候选**再跑 `_blob_pixels()` —— MicroPython 里逐像素 `get_pixel`，
   一块 30×30 就是 900 次调用 ≈ 1.5ms，几十个候选直接上百毫秒。

另外 `KERNEL_SIZE=3` 的形态学、`relax` 双扫、亮核回退（再扫一次全图/大块）
都是叠加成本。日志里 `lms 110/142/194/209ms` 就是这么来的。

**现在只用 cv_lite**（C 实现的连通域），且只处理 120×120 的 ROI：

| 操作 | 实测 |
| --- | --- |
| `gray.crop(roi=120x120)` + `to_numpy_ref()` | 0.30 ms |
| `cv_lite.grayscale_find_blobs` 120×120 | **0.20 ms** |
| 同上，640×480 全图（对照，未使用） | 4.10 ms |

`lms` 只统计「裁剪 + cv_lite」，**实测 mean 1.03ms / p95 2ms / max 3ms**。

## 2. 现在的模块（约 250 行，无任何状态机）

```python
CFG = {
    "roi": (260, 220, 120, 120),   # 画面中心 120x120
    "threshold": (220, 255),       # 灰度阈值（唯一要调的参数）
    "min_area": 6,
    "kernel_size": 1,              # 1=不做形态学（3 会抹掉 3~4px 光斑核心）
    "center_bias": 0.35,           # 选最大 blob 时"离 ROI 中心远"打折（可设 0）
    "center_ref_px": 60.0,
    "diag_mode": 0,
}
```

`sample(gray_img)` 流程只有四步：裁 ROI → cv_lite → 取面积最大 → 返回。
坐标已加 ROI 偏移，是 **640×480 原图坐标**。

**没有**：`prior`、`score`、`pending`、`jump_confirm`、状态机、卡尔曼。
`load()/set_calib()` 保留成空函数只为兼容旧调用方。

## 4. 阈值怎么定（实测扫描，本机现场）

| THRESHOLD | raw | 结果 |
| --- | --- | --- |
| 200 | 2 | 选对（激光 345 vs 反光 322，**余量小**） |
| 210 | 2 | 选对（294 vs 196） |
| **220** | 2 | **选对（273 vs 156，余量 1.75×）← 默认** |
| 230 | 3 | **选错**：激光被拆成两片，反光反而最大 |
| 240 | 3 | 选错，同上 |
| 245 | 1 | 只剩激光碎片（偏心） |

**结论：220 是这台机器当前光照下的最佳点。** 阈值不是越高越好——
太高会把激光自身拆碎。

### 红占优判据（白物门控，可选）

灰度上无法区分"激光"和"同尺寸白点"，于是加一条**颜色**判据：在候选
**自己的 bbox 内**统计满足 `R-G > 60 且 R > 180` 的像素占比，
低于 `red_frac` 就换成**下一个**候选（不是直接丢帧）。

为什么不用"红色团距离/bbox 包含"这类几何判据：红背景会把它们全污染
（白圆柱 ROI 里一个 7987px 的红团 bbox 几乎覆盖整个窗口，导致误放行）。

离线/实拍实测（真实帧）：

| 候选 | bbox 内红占优比例 |
| --- | --- |
| **激光** | **100%** |
| 白色圆柱边缘 | 1% |
| 笔电白屏 | 0% |
| 白瓶 | 0% |

板端确认：激光像素 = `R253 / G91 / B93`（R−G=162），通道顺序为 RGB。
默认 `red_frac = 0.35`（留余量）。

开销：一次 `crop(120x120)` + 每候选 bbox(≈80px) 的 3 次数组取值，
实测整体 `lms` 从 1.03ms → **约 2ms**，仍远低于 10ms 门限。

接口：`sample(gray_img, rgb_img=None)`；不传 RGB 时自动退化为纯灰度
（`red_gate` 关闭）。预览里已经传了 chn2（RGBP888）。

> 注意：激光**关掉**时，红判据会把所有白亮点都拒掉 → 输出 `NONE`，
> 这是预期行为（没有红点就不该报激光）。

### 白色物体误判（用户重点提醒）

用类（含尺寸门限）对 5 个 ROI 实测：

| ROI | 结果 | 说明 |
| --- | --- | --- |
| 笔电白屏 | **NONE**（被 `max_side` 拒） | 大片白 **18×80 = 1440px** |
| 白瓶 | **NONE** | 阈值 220 就没进来 |
| 白墙 | **NONE** | 同上 |
| **白色圆柱边缘** | ❌ **(199,337) 8×13 = 104px** | 与激光 8×10=80px **同尺寸**，峰值也**都是 255** |
| 激光区 | ✅ (279,280) 8×10 | — |

新增两条上限（都是 O(1) 判断，不动算法结构）：

```python
"max_side": 40,    # 单边 > 40px -> 大片白（屏幕/墙/灯）
"max_area": 600,   # 面积 > 600px -> 同上
```

**结论**：白屏/白墙/白灯这类"大片白"已经被挡住；但**与激光同尺寸的白边**
（如白色圆柱、白纸边缘）在灰度上无法区分——它同样过曝到 255。
可行对策（按优先级）：

1. **把 ROI 对准激光、让白色物体落在窗口外**——本例里圆柱在 (199,337)，
   激光 ROI 是 x 260~380，本来就不重叠，所以实际不受影响；
2. 收紧 `max_side` / `max_area` 到更贴近激光的尺寸（如 24 / 400）；
3. 若必须区分"红激光 vs 白物体"，只能上**颜色**判据（红占优）：
   `cv_lite.rgb888_find_blobs` 在 120×120 上开销很小，但需要 RGB888 通道；
   上一代实现用过全图 RGB888 是 13~16ms，ROI 内会低很多——这一轮按"极简灰度"
   要求没有引入。

| 指标 | ROI 120×120 | ROI 80×80 |
| --- | --- | --- |
| 检出率 | **100%（1935/1935）** | **100%（1934/1934）** |
| 最大连续丢失 | **0 帧** | **0 帧** |
| 相邻位移 mean / p95 | 2.17 / 6.32 px | **1.88 / 4.00 px** |
| 相邻位移 max | 66.4 px | **48.2 px** |

### ⚠ 重要发现：转 pan 几乎不会让光斑在画面里移动

实测"pan 指令 vs 光斑 meanX"：

| pan | 光斑 meanX |
| --- | --- |
| 1500 | 278.5 |
| 1580 | 275.2 |
| 1420 | 255.6 |

160µs 转角只让光斑移动约 **23px（≈0.14 px/µs）**；如果激光固定在房间、
只有相机转动，按 FOV 估算应该是 0.4~1 px/µs（约 60~160px）。
说明**激光与相机是共装的**（这正是"激光笔和相机相对位置固定"的物理含义），
所以转云台时**两者一起动、光斑在画面里几乎不动，变的是背景**。

因此：

- 上面的"运动测试"严格说是**背景运动**测试——算法在背景变化时仍 100% 锁定；
  偶发的 y 跳变是"背景里某个反光点瞬间变大、抢过激光"；
- **要真正测激光运动，必须移动激光笔本身**（手拿着移动，或用独立的激光支架），
  转云台是测不出来的。

## 8. 方案 B：红掩码作主检测（2026-10-22 深夜）

### 为什么必须换判据

现场实测（激光打在**棕色木墙**上，就在红袋子上方）：

| 目标 | 灰度 | RGB | R−G |
| --- | --- | --- | --- |
| 激光外圈（红晕） | **123~160** | (255, 76,137) | **~150** |
| 激光中心（白核） | 255 | (255,216,232) | 39 |
| 白色物体 | 229+ | (240,252,248) | −12 |
| 棕色木纹 | ~150 | (160,150,120) | ~10~60 |

结论：**激光是"红且亮"，白物是"亮但不红"，木纹是"红但不亮"**。
灰度阈值 220 只框得住白核（5×6），而白核 RGB 是过曝白、`red_frac=0.28`
→ 基于 bbox 的颜色门控在这个目标上不成立。

### 实现要点（踩了三个坑）

1. **uint8 相减会溢出回绕**：`R - G` 在 uint8 上会 wrap，掩码几乎全白。
   用 `(G <= 255-dg) & (R > G+dg)` 等价实现 `R-G>dg` 且不溢出
   （实测与 int16 真值**逐像素 0 不一致**，且 1ms vs 3ms）。

2. **`img.crop()` 出来的 RGBP888 数组和画面不一致**：同样的
   `to_numpy_ref()`，整帧数组再切片是准的，`crop()` 的结果对不上
   （掩码里出现只有木纹、没有激光的怪现象）。
   → 必须 `full = img.to_numpy_ref()` 然后 `full[:, y0:y0+rh, x0:x0+rw]`。

3. **`min_area` 是 bbox 面积**（用合成矩形 20×30 单元测试确认）。
   木纹是 8×2 的细条，红袋子是编织纹理，都会在 `min_area` 下被切碎。

4. **必须加 `R>200`**：木纹 R≈160 也满足 `R-G>60`，不加这条会把墙纹
   全收进来（实测红块连成横贯全宽的条，把激光并进去）。
   `R>200` 后木纹被排除，激光（R=255）留下。

### 参数与结果

```python
"roi": (207, 168, 80, 80),   # 激光在 (247,209)，ROI 以它为中心
"red_primary": 1,            # 红掩码主检测
"red_dg": 60,                # R-G 阈值
"red_rmin": 200,             # 红色亮度下限（排木纹/棕墙）
"red_min_area": 40,          # 掩码连通域最小 bbox 面积
"auto_roi": 1,               # 丢失 2 帧后扫 4x3 块自动挪 ROI
```

固定 ROI 15 秒实测（4 组参数都 100%）：

| ROI | 命中 | lms | 位置 | std |
| --- | --- | --- | --- | --- |
| **(207,168,80,80)** | **100%（854/854）** | **0.78 ms** | (247.6, 209.7) | **0.65 / 1.30** |
| (197,158,100,100) | 100% | 1.02 ms | (247.4, 210.5) | 1.93 / 4.71 |
| (217,178,60,60) | 100% | 0.63 ms | (244.2, 206.6) | 2.65 / 2.51 |
| rmin=150（含木纹） | 99.9% | 0.78 ms | (241.6, 204.9) | 0.44 / 0.35 |

> `rmin=150` 时 std 更小但**质心偏 6px**——木纹把重心拽过去了，所以 200 才对。

30 秒长跑（含一次激光移动）：73.6%，中间有 161 帧丢失，之后被 `auto_roi`
重新捕获；固定不动的 15 秒段都是 100%。**说明残留问题在"激光离开 ROI 后
的重捕"，不在检测本身。**

## 9. 比例判据 + 孤立性判据（2026-10-23 凌晨）

### 固件限制：关不掉自动增益/白平衡

```
set_auto_gain(False)     -> not support set_auto_gain now...  (抛异常)
set_auto_whitebal(False) -> not support set_auto_whitebal now...
set_auto_exposure(False) -> not support set_auto_exposure now...
```

三个方法**存在但未实现**。所以颜色基准会随 AE/AWB 漂移，这是早期数据
反复矛盾的隐藏原因（同一位置在不同脚本里 R 从 255 掉到 87）。

### 比例判据（模拟 LAB 的 A 通道，抗曝光漂移）

绝对门限 `R>200` 会随整体亮度漂；改用比例：

```python
cond = (R > rmin) & ((R-G) > dg) & (R/(R+G+B) > red_ratio)
```

实测（现场像素）：激光红晕 **0.545**、白物 0.324、木墙 0.372、红袋 0.547。
取 `red_ratio=0.45` 可排除白物和木墙，且不随亮度变化。

实现注意：

- **ulab 没有 `int32`**，`R*100` 会溢出；`rat=0.45` 时用等价式
  `R*20 > 9*(R+G+B)`（两端 <6900，int16 安全），其他比例用 float；
- 仍保留 uint8 安全的 `(G<=255-dg)&(R>G+dg)` 写法。

### 孤立性判据（排掉"嵌在大片红里的碎片"）

红袋子也是饱和红，且其碎片尺寸可能落在激光的尺寸范围内。激光是**孤立点**，
袋子是**大片红**。检查候选 bbox **外圈 band=2px** 内的红色占比，超过
`iso_max=0.35` 就丢弃。

### 云台自由摆动实测（26s，pan/tilt 大角度快速来回，画面内无激光）

| 配置 | 误报率 | lms |
| --- | --- | --- |
| 红掩码 + 尺寸上限（rmin=200） | 22.5% | 15.3 ms（auto_roi 拖慢） |
| rmin=240 | 4.0% | 19.5 ms |
| rmin=240 + auto_roi 关 | 27.3% | 3.65 ms |
| **rmin=240 + 孤立性判据** | **7.0%** | **3.66 ms** |

> 中途 `rmin=240` 一度看起来把误报压到 4%，那是 `auto_roi` 把 ROI 挪走了的
> 假象；关掉 auto_roi 后误报回到 27.3%，所以真正起作用的是**孤立性判据**。

### 正例验证未完成

这轮多次尝试都没能同时在"激光在 ROI 内"时采集数据：

- 截图确认激光在 **(345,257)**（靶纸左侧），而当时 ROI 在 (207,168) —— 差 38px；
- 把 ROI 移到 (295,207) 后重测，又一次采到了激光不在 ROI 的时刻
  （ROI 内最红只有 R−G=30 的暗棕像素）。

**下一步**：写一个自包含脚本——先用带孤立性判据的全帧扫描定位激光，
再原地设置 ROI 并连续测 20s，最后同一次运行里做云台摆动，避免跨脚本
场景漂移。

### 实现（按需求，无卡尔曼/无舵机映射）

- 模块级 `last_x/last_y`，初始 `start_x/start_y`（默认画面中心）；
- 每帧 ROI 中心 = `(last_x, last_y)`，`roi_size=120`，边界裁剪；
- 成功：`last_x/last_y = 本帧坐标`；
- 失败：保持不变，连续失败 > `lost_reset=30` 帧才回起始点；
- 颜色门控全关（`red_primary=0, red_ratio=0, red_gate=0`），只走灰度阈值 220；
- 保留 merge 与尺寸门限（`max_side=40, max_area=600`）。

### 三轮实测（每轮 30s，用户手动横移）

| 轮次 | 关键改动 | 检出率 | <20px 占比 | 最大连续丢失 | lms |
| --- | --- | --- | --- | --- | --- |
| 1 | ROI120 + 面积选择(bias 0.35) | **100%** | 92.4% | **0** | 0.94 ms |
| 2 | ROI140 + bias 0.65 | 92.3% | 85.8% | 32 | 1.08 ms |
| 3 | **ROI120 + 距离选择(select_near)** | 76.7% | **95.6%** | 216 | 1.02 ms |

**第 2 轮说明**：放大 ROI 反而引入更多干扰 blob，检出率与跳变同时变差 → 回退。

**第 3 轮说明**：`J` 行日志证明跳变原因是"同一帧有 3~4 个尺寸相近的候选、
按面积选会来回跳"，改成"选离 ROI 中心最近"后跳变从 85.8% → **95.6% 达标**；
但代价是**假锁定会自我强化**（选最近的 → 最近的总是那个假目标），
一旦真激光离开 120px 窗口就再也回不来，产生一次 216 帧连续丢失。

### 第一轮的分段数据（重要）

第 1 轮虽然总跳变 92.4% 不达标，但按时间段拆开：

| 时间段 | <20px 占比 |
| --- | --- |
| 0–7s（启动） | 80.5% |
| 7–14s | **99.5%** |
| 14–21s | **98.0%** |
| 21–28s | 91.0% |

即**锁定之后稳定在 98~99.5%**，总指标被启动阶段拖低。

### 结论与下一步

小 ROI + 跟随的组合，在"激光每帧位移 < 60px"时非常稳（98%+），
问题是**丢失后的重捕**：需求里的"连续失败 30 帧回画面中心"没用，
因为激光不在中心。

建议下一步把重捕改成**局部扩窗搜索**：连续丢失 5/10/20 帧时，
把 ROI 依次放大到 180 / 240 / 320 再搜，找到后立刻收回 120。
这不是卡尔曼也不是状态机，只是搜索窗口随丢失时长增长。
